CSV vs TSV: what is the difference and which should you use?

Both are plain-text tables. The only difference is the character between the fields, and that one difference decides how often the file breaks.

The basic difference

A CSV (comma-separated values) file puts a comma between fields. A TSV (tab-separated values) file puts a tab character there instead. Each line is one record, and the first line usually holds the column names.

name,city,notes
Anita Sharma,Pune,"Prefers email, not phone"
name	city	notes
Anita Sharma	Pune	Prefers email, not phone

Notice what happened to the third field. In the CSV it needed quotes, because it contains a comma. In the TSV it needed nothing.

Why the delimiter matters

Commas are everywhere in real data: addresses, company names, sentences, numbers written with thousands separators. Every one of them has to be protected with quoting, and every program that writes or reads the file has to apply the quoting rules correctly. Tabs, by contrast, almost never occur inside a value. A person typing into a form cannot easily enter one. That makes TSV much harder to break by accident.

How CSV protects its values

The usual rules, described in RFC 4180, are:

  • A field containing a comma, a double quote or a line break is enclosed in double quotes.
  • A double quote inside such a field is written as two double quotes.
  • Line breaks are allowed inside a quoted field, so one record may cover several lines.

These rules work, but only when everyone follows them. Files produced by joining values with commas in a script, without quoting, are a constant source of shifted columns.

How TSV protects its values

TSV takes the opposite approach. In its simplest and most common form, a field simply may not contain a tab or a line break, and there is no quoting at all. Software that has to store such characters either replaces them with a space or writes them as the escape sequences \t and \n. Because there are no quotes to interpret, a TSV file can be split correctly with nothing more than "break on newline, then break on tab", which is why it is popular for logs, bioinformatics data and command-line tools such as cut and awk.

The last row surprises people. When you copy a range of cells from Excel or Google Sheets and paste it into a text box, the clipboard contains tab-separated text. If you paste spreadsheet cells into a converter, treat the input as TSV.

The semicolon variant

In countries where the comma is the decimal separator, a comma between fields would be ambiguous: is 3,14 one number or two fields? Spreadsheet programs in those locales therefore write "CSV" files with semicolons between fields. The file extension is the same, so the only way to know is to open the file in a text editor and look. This is the most common reason a CSV opens with everything in one column.

Problems the two formats share

Changing the delimiter does not fix what spreadsheets do to the values themselves:

  • Leading zeros disappear. 00719 becomes 719.
  • Long numbers are rounded. Anything beyond 15 digits, such as a card number, loses its final digits and is shown in scientific notation.
  • Text becomes dates. Values such as 1-2 or SEPT2 may be converted to dates.
  • Encoding. A file saved in a legacy encoding shows accented and non-Latin characters as nonsense. Save and read as UTF-8.
  • No types. Neither format records whether a column is a number, a date or text. That information lives only in the head of whoever made the file.

The fix for the first three is the same in both cases: import the file and mark those columns as Text, or do not round-trip important identifiers through a spreadsheet at all.

Which should you choose?

  • Use CSV when the file is going to another person or into a product's import screen. It is the format everyone expects.
  • Use TSV when you control both ends, when the data contains a lot of free text, or when the file will be processed with scripts.
  • If the data is nested or has types that matter, neither is a good fit; use JSON.
