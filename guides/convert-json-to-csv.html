How to convert JSON to CSV

JSON can be any shape. CSV is always a rectangle. Converting means deciding how the first fits into the second.

The shape that converts cleanly

CSV is a grid: every row has the same columns, and every cell holds one value. JSON converts to that without any decisions when it is an array of objects whose values are all simple.

[
  { "id": 1, "name": "Alice", "active": true },
  { "id": 2, "name": "Ravi", "active": false }
]
id,name,active
1,Alice,true
2,Ravi,false

Each object becomes a row, and the keys become the header. In Data Ekam, paste the JSON on the Transform tab, open Convert and choose CSV, or choose Excel (XLSX) if a spreadsheet is the real destination.

When objects have different keys

API responses often omit keys that have no value. One record has a phone, the next does not. A table still needs one column per key, so the header should be the union of every key that appears in any object, and a record that lacks a key gets an empty cell in that column. Data Ekam builds the header this way. After converting, check that the header contains every field you expect; a field that only appears in the 500th record is easy to overlook.

Nested objects

A value that is itself an object has no single cell to live in.

{ "id": 1, "address": { "city": "Pune", "pincode": "411001" } }

There are two common ways to handle it:

  • Flatten with joined names. Produce columns called address.city and address.pincode. This is what most people want for analysis, because each piece of data ends up in its own column.
  • Keep it as text. Put the nested object into one cell as a JSON string. Nothing is lost and the conversion can be reversed, but the cell is not directly usable in a spreadsheet.

Data Ekam flattens nested objects with joined names, so the example above produces the columns id, address.city and address.pincode. If you need a different layout, reshape the JSON first and then convert; the result of converting flat JSON is predictable in any tool.

Arrays inside records

Arrays are the harder case, because they hold a variable number of items.

{ "order": 1001, "items": [ { "sku": "A1", "qty": 2 }, { "sku": "B7", "qty": 1 } ] }

There are three ways to handle them, and the right one depends on the question the spreadsheet has to answer. Data Ekam keeps one row per record and writes the array into a single cell as JSON text, which loses nothing; for the other layouts, reshape the JSON before converting.

  • One row per item. Repeat the parent fields on each row: order 1001 appears twice, once for each SKU. Choose this when you will total or filter by item.
  • Numbered columns. items.0.sku, items.1.sku and so on. This keeps one row per order but creates as many column groups as the longest array.
  • Joined in one cell. For arrays of simple values, such as tags, a single cell containing red; cotton; sale is often enough.

A single object, or an object of objects

Not all JSON is an array. A single object converts to one data row. A wrapper such as { "data": [ ... ], "page": 1 } needs the inner array pulled out first, because the table you want is the list, not the envelope. An object keyed by ID, such as { "u1": {...}, "u2": {...} }, is a list in disguise; turn it into an array, moving the ID into each record, before converting.

Values that need quoting

A correct converter wraps any value containing a comma, a double quote or a line break in double quotes, and doubles any quotes inside it. If you ever build CSV by joining values with commas yourself, this is the step that gets forgotten, and the first address with a comma in it shifts every column after it.

Before you open it in Excel

Opening a CSV by double-clicking lets Excel guess the type of every cell, and it guesses aggressively:

  • Long digit strings such as card or IMEI numbers are shown in scientific notation and lose their final digits.
  • Leading zeros are removed from codes like 00719.
  • Text such as 3-4 or MAR1 may be turned into a date.

To avoid this, import the file through Excel's Data tab and set those columns to Text, or convert straight to Excel (XLSX) in Data Ekam so the file you open is already a workbook.

What cannot make the round trip

CSV does not record types. Once converted, the number 1, the string "1" and the boolean true are all just text, and null and an empty string look the same. If you plan to convert the CSV back to JSON later, expect every value to return as a string.
