Markdown syntax guide: the essentials with examples

Markdown is plain text with a few punctuation conventions. You can learn the useful part in ten minutes.

What Markdown is

Markdown is a way of writing formatted documents in plain text. You mark a heading with a hash and a list item with a dash, and a renderer turns the file into HTML. The source stays readable even when it is not rendered, which is why it is used for README files, documentation, notes, chat messages and static websites. A Markdown file usually has the extension .md.

Headings

# Page title
## Section
### Subsection

One to six hashes give heading levels one to six. Put a space after the hashes; #Title without a space is not a heading in most renderers. Use one level-one heading per document and do not skip levels.

Paragraphs and line breaks

A blank line starts a new paragraph. A single line break inside a paragraph is ignored: two lines of text separated by one press of Enter are joined into one line when rendered. This is the most common surprise for new users. To force a line break without starting a new paragraph, end the line with two spaces or a backslash.

Emphasis

*italic* or _italic_
**bold**
***bold and italic***
~~struck through~~

Strikethrough is an extension, supported on GitHub and by most modern renderers but not part of the original syntax.

Lists

- Apples
- Oranges
  - Blood oranges
  - Navel oranges

1. Preheat the oven
2. Mix the batter
3. Bake for 25 minutes

Unordered lists use -, * or +; pick one and stay with it. Ordered lists use a number and a full stop. Indent nested items so they line up with the text of the parent item. Leave a blank line before the first item of a list, because some renderers will otherwise treat the list as part of the paragraph above.

Links and images

![Logo of the project](images/logo.png)

A link is the visible text in square brackets followed by the address in round brackets. An image is the same with an exclamation mark in front, and the text in square brackets becomes the image's alternative text, which screen readers announce and which is shown if the image fails to load. Write it as a description of the picture.

Code

Wrap a short piece of code in single backticks to show it inline. For a block, put three backticks on the line before and the line after, optionally naming the language for syntax colouring:

```json
{ "name": "Alice", "age": 30 }
```

Nothing inside a code block is interpreted as Markdown, so it is also the way to show characters such as asterisks and hashes literally.

Quotes and rules

> This is a quoted paragraph.

---

A greater-than sign starts a block quote. Three dashes on a line of their own, with blank lines around them, draw a horizontal rule.

Tables

| Format | Comments | Typed |
|--------|:--------:|------:|
| JSON   | No       | Yes   |
| CSV    | No       | No    |

Tables are another widely supported extension. Columns are separated by pipes, and the second line of dashes separates the header from the body. Colons in that line set the alignment: on the left for left-aligned, on both sides for centred, on the right for right-aligned. The pipes do not need to line up in the source, although it is easier to read when they do. A cell cannot contain a line break, and a pipe inside a cell must be written as \|.

Escaping special characters

To show a character that Markdown would otherwise interpret, put a backslash before it: \*not italic\* displays the asterisks. This matters most for asterisks and underscores in the middle of text, and for a number followed by a full stop at the start of a line, such as a year, which would otherwise begin a numbered list.

Mistakes that stop Markdown rendering

  • No space after #, - or 1..
  • No blank line before a list, a table or a code block.
  • Nested list items indented by too little, so they join the parent level.
  • A code block opened with three backticks and never closed, which turns the rest of the document into code.
  • Text indented by four or more spaces, which many renderers treat as a code block.
  • Trailing spaces left at the ends of lines, which create unintended line breaks.

Flavours

There is no single Markdown. The original description left details open, so renderers differ at the edges. CommonMark is a precise specification of the core syntax, and GitHub Flavored Markdown adds tables, task lists, strikethrough and automatic links on top of it. Everything in this guide except tables and strikethrough works everywhere; those two work almost everywhere. If your document will be published on a particular platform, preview it there before relying on anything unusual.

Markdown and HTML

Each Markdown construct corresponds to an HTML element: a level-two heading becomes <h2>, a paragraph becomes <p>, bold becomes <strong>, and a list becomes <ul> or <ol> with <li> items. You can also write HTML directly in a Markdown file when you need something Markdown lacks, although some platforms remove it for security reasons.

Working with Markdown in Data Ekam

On the Transform tab, paste the Markdown and choose Format, then Markdown, to tidy a file. With Clean ticked, trailing spaces are trimmed and runs of several blank lines are reduced to one, so paragraph and list breaks are kept while the stray spacing that causes rendering surprises is removed. To see what changed between two versions of a document, paste them into the Compare tab; because Markdown is plain text, a line-by-line comparison shows edits clearly.
