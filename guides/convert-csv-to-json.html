How to convert CSV to JSON

The conversion looks trivial until a comma appears inside a value. Here is how it works and what to check.

How rows become objects

A CSV file is a table: the first line usually names the columns, and each line after it is one record. The natural JSON equivalent is an array with one object per row, where the column names become keys.

name,age,city
Alice,30,Pune
Ravi,41,Chennai
[
  { "name": "Alice", "age": "30", "city": "Pune" },
  { "name": "Ravi", "age": "41", "city": "Chennai" }
]

Doing it in Data Ekam

  1. Open the Transform tab and paste the CSV, or drop the .csv file onto the input box.
  2. Open the Convert menu and choose JSON.
  3. Review the preview, then use Copy for the text or Download for a .json file.

The file is read by your browser and is not uploaded, so this is safe to do with data you cannot share.

Why every value is a string

In the example above, "age": "30" is a string, not the number 30. This is deliberate. CSV has no types; every cell is text. A converter that guesses will turn the postcode 02134 into 2134, the product code 1E5 into 100000, and a 16-digit account number into a rounded floating-point value. Keeping values as strings loses nothing. If your program needs numbers, convert the specific columns you know are numeric after loading the JSON.

Quotes, commas and line breaks inside values

The CSV rules that cause most broken conversions are about quoting:

  • A value containing a comma must be wrapped in double quotes: "Sharma, Anita".
  • A double quote inside a quoted value is written twice: "She said ""yes""".
  • A quoted value may contain a line break, so one record can span more than one line of the file.

If your JSON has more keys than expected, or the columns shift part-way down, an unquoted comma or an unclosed quote is almost always the cause. Find the first row that looks wrong and check the row above it as well.

The header row

The first row supplies the keys, so it is worth cleaning before converting:

  • Duplicate names. Two columns called id cannot both be keys in one object; one will overwrite the other. Rename them first.
  • Blank names. A trailing comma in the header creates a column with no name.
  • Spaces and capitals. First Name is a legal JSON key but an awkward one in code. Many people rename to first_name before converting.
  • No header at all. If the file starts directly with data, add a header line, otherwise the first record will be used as the key names.

Empty cells

An empty cell becomes an empty string, "". That is different from JSON null and different from a key that is missing altogether. Systems that distinguish between "blank" and "not provided" will care, so decide which you need and adjust after conversion.

It is not always a comma

In many European locales, where the comma is the decimal separator, spreadsheet programs export "CSV" files that use semicolons between fields. Tab-separated files are also common and often carry a .csv or .txt extension. If the whole of each row lands in a single key, the delimiter is not what the converter expected. For tab-separated data, convert it as TSV; for semicolons, replace the delimiter first, taking care not to touch semicolons inside quoted values.

Flat in, flat out

CSV is flat, so the JSON you get is a flat list of flat objects. If the target needs nesting, for example an address object containing city and pincode, that reshaping is a separate step done in code after conversion. A column named address.city will simply become a key with a dot in its name.

A quick checklist

  • Does the number of objects equal the number of data rows in the file?
  • Does every object have the same keys?
  • Did values with leading zeros keep them?
  • Do names with accents or non-Latin scripts display correctly? If not, the file was not saved as UTF-8.
